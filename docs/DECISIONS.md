# 架构决策记录

本文件记录会影响后续实现的重要决定。新决定按时间追加，不覆盖历史内容。

## ADR-001：使用独立的内部几何模型

- 状态：已接受
- 日期：2026-10-05

### 决定

在 libcdr、DXF、OpenCASCADE 和 Qt 之间建立项目自有的 `GeometryDocument`，所有第三方格式先转换到该模型。

### 原因

- 隔离第三方库接口变化；
- 便于测试格式转换误差；
- 允许替换 DXF 或 CDR 后端；
- 避免界面代码承担格式解析职责。

## ADR-002：第一阶段实现最小 DXF Writer

- 状态：已接受
- 日期：2026-10-05

### 决定

第一阶段自行实现项目所需的 ASCII DXF 输出子集，不直接链接 GPL 许可的 libdxfrw。

### 原因

- 第一阶段只需少量二维实体；
- 更容易控制曲线映射和单位；
- 避免过早确定整个项目的许可证；
- libdxfrw 仍可用于行为参考和独立交叉验证。

## ADR-003：OCCT 不负责默认 DXF 导入

- 状态：已接受
- 日期：2026-10-05

### 决定

OpenCASCADE 用于几何、拓扑和容差分析，不作为默认 DXF 读取后端。

### 原因

开源 OCCT 本体没有可直接依赖的免费 DXF 数据交换组件。将格式读写与几何计算分开也更符合项目模块边界。

## ADR-004：阶段 A 使用内建最小测试框架

- 状态：已接受
- 日期：2026-10-06

### 决定

阶段 A 的纯核心测试继续使用 `tests/core/dsh_test.hpp`，不为当前规模引入 GoogleTest/Catch2。测试写法保持“注册用例 + 独立断言”的通用结构，项目扩大后可迁移。

### 原因

- 保持 `core-msvc` 零外部依赖；
- 当前框架已覆盖参数单次求值、非有限值、绝对/相对误差等关键语义；
- 避免在几何接口尚未稳定时增加包管理变量。

## ADR-005：删除 Python/UI 原型，正式代码统一使用 C++

- 状态：已接受
- 日期：2026-10-06

### 决定

删除仓库根目录的早期 Python 转换/分析/UI 原型，以及临时验证 UI。正式实现统一进入 `src/` 与 `tests/core/`；Qt UI 等核心分析和 DXF 往返链路稳定后再实现。

### 原因

- 防止 Python 与 C++ 两套实现出现行为和精度差异；
- 避免临时 UI 被误认为已交付能力；
- 让代码审查、构建和测试围绕唯一的正式技术栈进行。

### 影响

被删除的原型仍可通过 Git 历史恢复。Qt 6 的最终链接方式与发布许可证安排仍需在实现界面前单独确认。

## ADR-006：区分“声明闭合”与“有效闭合轮廓”，警告携带实体来源

- 状态：已接受
- 日期：2026-10-07

### 决定

阶段 A 的分析器只报告 `Polyline::closed` 的源数据语义，字段命名为
`declaredClosed` / `declaredClosedPolylineCount`，不把它描述成经过拓扑验证的有效闭合轮廓。
声明闭合但长度为零的折线保留在声明计数中，同时产生退化警告。

`DocumentMetrics::warnings` 使用 `AnalysisWarning`，每条警告携带可选实体 ID；文档级警告的
ID 为空，实体原始警告和分析器生成警告携带实体 ID。

### 原因

- 端点连接、非零面积和自交检查属于后续拓扑分析，不能由一个布尔标志冒充；
- 保留源数据闭合标志有利于格式往返和问题定位；
- UI 必须能准确显示哪一个实体产生了警告，扁平字符串列表会丢失来源。

## ADR-007：最小 Writer 输出真正的 ASCII DXF R12

- 状态：已接受
- 日期：2026-10-07

### 决定

最小 Writer 输出 `AC1009`（R12）。内部 `Polyline` 写为传统
`POLYLINE` + `VERTEX` + `SEQEND` 序列，不在 R12 文件中写后续版本的 `LWPOLYLINE`。
R12 图层名限制为最多 31 个 ASCII 字符，只允许字母、数字、`$`、`_`、`-`。

Writer 在输出前完整验证文档；非毫米单位、非恒等变换、非有限数值、不可写出的退化圆/圆弧、
空折线、重复或不兼容图层均明确失败。文本先在内存生成，再写入目标，避免验证失败时截断文件。

### 原因

- `AC1009 + LWPOLYLINE` 是自相矛盾的版本声明；
- 完整 R2000 对象图还需要句柄、所有者关系与更多表记录，不应实现半套格式；
- R12 传统二维实体简单、可独立审查，并更适合第一阶段的机械软件兼容性目标；
- 对无法无损表达的输入显式失败，比静默忽略变换或写出退化实体更安全。

## ADR-008：Reader 采用“结构严格、内容宽容”的 R12 子集策略

- 状态：已接受
- 日期：2026-10-07

### 决定

Reader 只承诺正确读取本项目 Writer 产生的 ASCII DXF R12 子集。空文件、二进制输入、非整数组码和
奇数组码/值行属于无法建立记录边界的致命结构错误；未闭合 SECTION、缺 EOF、支持字段损坏、缺字段和
未知实体属于可恢复内容问题，通过 `DxfReadResult::warnings` 上报。

额外且不影响当前二维几何的组码允许忽略；但已知会改变几何含义的传统 `POLYLINE` 标志
（mesh、polyface、3D 等）或非零 bulge 不得当作普通直线折线读取，必须跳过整个实体并告警。

### 原因

- 没有可靠的组码/值配对时继续解析会造成记录错位，不能声称结果可信；
- 对局部字段使用默认值并保留行号警告，适合 UI 展示和人工修复；
- DXF 中 bulge 和 polyface 具有明确的曲线/拓扑语义，静默压平会得到“看似成功但几何错误”的结果；
- 限定子集比实现半套通用 DXF Reader 更可审查，也为后续替换独立后端保留边界。

# 架构决策记录

本文件记录会影响后续实现的重要决定。新决定按时间追加，不覆盖历史内容。

## ADR-001：使用独立的内部几何模型

- 状态：已接受
- 日期：2026-10-05

### 决定

在 libcdr、DXF、OpenCASCADE 和 Qt 之间建立项目自有的 `GeometryDocument`，所有第三方格式先转换到该模型。

### 原因

- 隔离第三方库接口变化；
- 便于测试格式转换误差；
- 允许替换 DXF 或 CDR 后端；
- 避免界面代码承担格式解析职责。

## ADR-002：第一阶段实现最小 DXF Writer

- 状态：已接受
- 日期：2026-10-05

### 决定

第一阶段自行实现项目所需的 ASCII DXF 输出子集，不直接链接 GPL 许可的 libdxfrw。

### 原因

- 第一阶段只需少量二维实体；
- 更容易控制曲线映射和单位；
- 避免过早确定整个项目的许可证；
- libdxfrw 仍可用于行为参考和独立交叉验证。

## ADR-003：OCCT 不负责默认 DXF 导入

- 状态：已接受
- 日期：2026-10-05

### 决定

OpenCASCADE 用于几何、拓扑和容差分析，不作为默认 DXF 读取后端。

### 原因

开源 OCCT 本体没有可直接依赖的免费 DXF 数据交换组件。将格式读写与几何计算分开也更符合项目模块边界。

## ADR-004：阶段 A 使用内建最小测试框架

- 状态：已接受
- 日期：2026-10-06

### 决定

阶段 A 的纯核心测试继续使用 `tests/core/dsh_test.hpp`，不为当前规模引入 GoogleTest/Catch2。测试写法保持“注册用例 + 独立断言”的通用结构，项目扩大后可迁移。

### 原因

- 保持 `core-msvc` 零外部依赖；
- 当前框架已覆盖参数单次求值、非有限值、绝对/相对误差等关键语义；
- 避免在几何接口尚未稳定时增加包管理变量。

## ADR-005：删除 Python/UI 原型，正式代码统一使用 C++

- 状态：已接受
- 日期：2026-10-06

### 决定

删除仓库根目录的早期 Python 转换/分析/UI 原型，以及临时验证 UI。正式实现统一进入 `src/` 与 `tests/core/`；Qt UI 等核心分析和 DXF 往返链路稳定后再实现。

### 原因

- 防止 Python 与 C++ 两套实现出现行为和精度差异；
- 避免临时 UI 被误认为已交付能力；
- 让代码审查、构建和测试围绕唯一的正式技术栈进行。

### 影响

被删除的原型仍可通过 Git 历史恢复。Qt 6 的最终链接方式与发布许可证安排仍需在实现界面前单独确认。
